# ระบบลงเวลา

## การเตรียมใช้งาน

1. ผูกบัญชีผู้ใช้กับข้อมูลพนักงาน และกำหนดหัวหน้าตามโครงสร้างหน่วยงาน ผู้ดูแลระบบ (`admin`), ฝ่ายบุคคล (`hr`), ผู้อำนวยการที่กำหนดในค่าระบบ หรือผู้ได้รับสิทธิ์ `attendanceReview` สามารถตรวจสอบรายการได้ โดยห้ามอนุมัติรายการของตนเอง สิทธิ์ `attendanceReview` ต้องกำหนดผ่านระบบสิทธิ์เดิมหากต้องการใช้เพิ่มเติม
2. พนักงานกะใช้ตารางเวรที่เผยแพร่หรือปิดรอบแล้ว รวมกะข้ามวัน พนักงานปกติใช้ชุดเวลาที่กำหนดไว้ หากไม่มีข้อมูลเวลางานจะรับเวลาสแกนรอตรวจสอบโดยไม่สมมติเวลาเริ่มงาน
3. ผู้ดูแลกำหนดจุดลงเวลา พิกัด รัศมี และเปิดใช้งาน ทุกวิธีลงเวลาต้องส่ง GPS หากอยู่นอกพื้นที่ต้องระบุเหตุผล รายการใหม่รออนุมัติ
4. สำหรับโทรศัพท์ ให้ใช้ชื่อเว็บไซต์ HTTPS ที่โทรศัพท์เข้าถึงได้ แล้วเปิดรายละเอียดจุดลงเวลา > ป้าย QR สำหรับพิมพ์จากเว็บไซต์นั้น ป้ายที่สร้างผ่าน `127.0.0.1` ใช้ทดสอบบนเครื่องเท่านั้น
5. หน้าของฉันแสดงเวลาประเทศไทยและปุ่ม “สแกนเวลา” เมื่อกดจะอ่าน GPS ตรวจพื้นที่และบันทึก หากนอกพื้นที่ให้ระบุเหตุผลแล้วส่งรออนุมัติ ไม่ต้องเลือกเข้า–ออกหรือเวร สามารถใช้กล้องมือถือเปิดลิงก์จากป้าย QR เพื่อระบุจุดลงเวลาได้ และยังตรวจ GPS ฝั่งเซิร์ฟเวอร์

## ชุดเวลาปกติและ Profile

- ติดตั้งตารางเพิ่มเติมเฉพาะโมดูลนี้ด้วย `rtk docker exec -w /app dansai php yii migrate/up --migrationPath=@app/modules/attendance/migrations --interactive=0` ไม่มีการแก้รายการลงเวลาเดิมใน migration
- ผู้ดูแลเปิด `/attendance/schedule/index` สร้างชุดเวลา เช่น 08:00–16:00 หรือ 08:30–16:30 พร้อมวันทำงาน ผ่อนผันสาย และวันหยุดเพิ่มเติม ระบบใช้วันหยุดจากปฏิทินส่วนกลาง (`calendar` ประเภท `holiday`) ด้วย
- ไม่สร้างหรือผูกชุดเวลาให้พนักงานอัตโนมัติ ผู้ดูแลต้องยืนยันวันทำงาน/วันหยุดของแต่ละกลุ่มก่อนกำหนดใช้งาน
- เลือกหน่วยงานหรือพนักงานจากหน้าตั้งค่า หรือเปิด “รูปแบบและเวลาทำงาน” ใน Profile หัวหน้ากำหนดให้ผู้ใต้บังคับบัญชาและหน่วยงานที่ตนเป็นหัวหน้าได้ ผู้ใช้ทั่วไปดูอย่างเดียว
- ลำดับการใช้: ตารางเวรที่ประกาศ (รวมวัน OFF ซึ่งห้ามใช้เวลาปกติแทน) → ข้อยกเว้นปกติรายบุคคล → เวลาปกติของหน่วยงานที่ใกล้ที่สุดในโครงสร้าง โดยสองลำดับหลังใช้เฉพาะประเภทปกติ
- การกำหนดแต่ละครั้งมีวันที่เริ่มมีผลและเหตุผล เก็บรายการเดิมไว้ทั้งหมด ไม่แก้ชุดเวลาที่สร้างแล้ว หากเปลี่ยนให้สร้างชุดใหม่แล้วกำหนดใหม่ วันที่เริ่มมีผลต้องตั้งแต่วันนี้ ผลการจับคู่ที่บันทึกไปแล้วจะไม่ถูกเปลี่ยนอัตโนมัติ

## การจับคู่และการป้องกันซ้ำ

- เก็บเวลาสแกนและ GPS ต้นฉบับใน `data_json.raw_scan` แยกจากผลการจับคู่และประวัติแก้ไข
- จับคู่จุดเริ่มหรือจบงานที่ใกล้ที่สุดภายในช่วงกำหนด ชุดเวลาปกติกำหนดช่วงนี้ได้ ค่าเริ่มต้น 240 นาที; ตารางเวรใช้ 240 นาที หากใกล้เท่ากัน ไม่มีเวร หรือไกลกว่าช่วงกำหนด ให้เป็น `scan` รอหัวหน้าจับคู่ ไม่ใช้การสลับเข้า–ออกตามลำดับครั้ง และไม่ตีความเป็น OT อัตโนมัติ
- ผ่อนผันสายเริ่มต้น 0 นาที หากกำหนดมากกว่า 0 รายงานนับนาทีสายเฉพาะส่วนที่เกินช่วงผ่อนผัน
- ล็อกการส่งต่อพนักงานใน transaction สแกนซ้ำภายใน 120 วินาทีคืนรายการเดิม คำขอเดิม/การลองใหม่หลังการเชื่อมต่อขัดข้องใช้รหัสเดิม รวมถึงรหัสของคำขอซ้ำ เพื่อไม่สร้าง record ใหม่หลังพ้นช่วงป้องกัน

## การตรวจสอบและแก้ไข

- เมนู “รออนุมัติ → ลงเวลา” และตัวเลขใช้ query สิทธิ์ชุดเดียวกัน แสดงเฉพาะคำขอที่ยังดำเนินการได้ พร้อมปุ่มเปลี่ยนหน้า ประวัติของฉันกรองบัญชีเจ้าของฝั่งเซิร์ฟเวอร์เสมอ รวมถึงผู้ดูแล
- ใช้ “แก้ไข / ระบุเวร” เพื่อแก้วันเวลา ประเภทเข้า–ออก หรือเวร ต้องระบุเหตุผล ระบบเก็บประวัติและส่งอนุมัติใหม่ พร้อมป้องกันการเขียนทับจากหน้าที่เปิดค้างไว้
- ปุ่ม “ประเมินตามเวลางานใหม่” ในหน้าแก้ไขเสนอการจับคู่จากตารางเวร/เวลาปกติปัจจุบันให้ตรวจทานก่อนบันทึก ใช้เมื่อมีตารางเวรหรือชุดเวลาพร้อมภายหลังการสแกน
- รายการเก่าที่ยังไม่ผูกเวรต้องตรวจและระบุเวร ไม่ตีความช่องว่างของรายงานว่าเป็นผลการขาดงานที่ยืนยันแล้ว
- CSV รับ UTF-8 สูงสุด 5 MB / 5,000 แถว ใช้ตัวระบุพนักงานเพียงหนึ่งคอลัมน์ (`emp_id`, `cid` หรือ `code` ซึ่งหมายถึง CID เดิม) และ `checkin_at` รูปแบบ `YYYY-MM-DD HH:MM:SS` ดูตัวอย่างและคอลัมน์เพิ่มเติมที่หน้านำเข้า
- นำเข้า CSV ซ้ำจะข้ามรายการเดิม หากมีแถวผิดจะยกเลิกทั้งชุด รายการนำเข้ารออนุมัติและไม่ถือเป็นหลักฐาน GPS ที่ตรวจขณะลงเวลา
- รายงานและ Excel ใช้ข้อมูลเวรที่บันทึกไว้กับรายการ เพื่อรักษาประวัติเมื่อมีการแก้ตารางเวรภายหลัง

## การตรวจสอบก่อนส่งมอบ

ชุดทดสอบสำหรับฐานทดสอบเท่านั้น:

```sh
rtk docker exec -w /app dansai php tests/attendance_integration.php
rtk node --test tests/attendance_clock.test.cjs
```

ชุดทดสอบทำงานใน transaction และ rollback ข้อมูลทดสอบเมื่อจบ ครอบคลุม GPS, QR, กะข้ามวัน, การส่งซ้ำ, สิทธิ์อนุมัติ, การแก้ไขย้อนหลัง, CSV และความสอดคล้องของ Excel กับรายงาน ระหว่างรันทดสอบอาจล็อกแถวพนักงานชั่วคราว จึงควรหลีกเลี่ยงการลงเวลาพร้อมกัน

ชุดทดสอบ JavaScript จำลองผล GPS และเครือข่ายเพื่อทดสอบสถานะฟอร์ม ไม่เรียกอุปกรณ์จริง ตรวจผ่านเบราว์เซอร์: ฟอร์มสแกนปุ่มเดียว ประวัติส่วนตัว ส่วนเวลางานใน Profile หน้าตั้งค่า และทางเข้าคิวอนุมัติ

ยังต้องทดสอบบนโทรศัพท์จริงก่อนเปิดใช้: อนุญาต/ปฏิเสธ GPS, ในรัศมี/นอกรัศมีพร้อมเหตุผล, กล้องสแกนป้าย HTTPS, กะข้ามวัน และหัวหน้าตรวจอนุมัติครบขั้นตอน การทดสอบขนาดหน้าจอจำลองไม่ทดแทน GPS หรือกล้องจริง
