# Permission Matrix

ระบบแบ่งสิทธิ์เป็น 4 ระดับ ทุกการตรวจอยู่ที่ `services/DocumentAccessService` ที่เดียว

| ความสามารถ | ผู้ดูแลระบบ SOP | ผู้จัดทำหน่วยงาน | ผู้ตรวจ (ผอ./HR) | ผู้ใช้ทั่วไป |
|---|---|---|---|---|
| ดูเอกสารทุกสถานะ | ทุกหน่วยงาน | เฉพาะหน่วยงานตน | ทุกหน่วยงาน | ✗ |
| ดูเอกสารที่เผยแพร่แล้ว | ทุกหน่วยงาน | ทุกหน่วยงานที่ได้รับสิทธิ์ | ทุกหน่วยงาน | หน่วยงานตน / ที่ได้รับสิทธิ์ / ที่เป็นผู้รับ |
| สร้าง–แก้ไข | ทุกหน่วยงาน | เฉพาะหน่วยงานตน | ✗ | ✗ |
| กำหนดผู้รับเอกสาร | ✓ | เฉพาะหน่วยงานตน | ✗ | ✗ |
| ส่งอนุมัติ | ✓ | ✓ | ✗ | ✗ |
| เผยแพร่ / ส่งกลับแก้ไข | ✓ | ✗ | ✗ | ✗ |
| ลบฉบับร่าง | ✓ | เฉพาะหน่วยงานตน | ✗ | ✗ |
| เปิดสิทธิ์ข้ามหน่วยงาน | ทุกหน่วยงาน | เฉพาะผู้เป็นหัวหน้าหน่วยงาน | ✗ | ✗ |
| ตั้งค่าระบบ | ✓ | ✗ | ✗ | ✗ |

## RBAC permissions

- `medsop.admin` — ผู้ดูแลระบบ จัดการทุกหน่วยงาน เผยแพร่ ตั้งค่า
- `medsop.author` — ผู้จัดทำเอกสารของหน่วยงานตนเอง
- `medsop.review` — ดูเอกสารทุกสถานะ แต่แก้ไม่ได้
- `medsop.viewAll` — ดูเอกสารได้ทุกหน่วยงาน
- `medsop.viewPublished` — ดูเอกสารที่เผยแพร่แล้วตามสิทธิ์ผู้รับ

สร้างโดย migration `m260903_100000_create_medsop_permissions`

## Role mapping

`DocumentAccessService` รับทั้ง permission ชุด `medsop.*` และ role เดิมของระบบ
จึงมอบสิทธิ์จากหน้าจัดการผู้ใช้ (role) ได้โดยไม่ต้องผูก permission ทีละรายการ

| ระดับสิทธิ์ | RBAC item ที่ยอมรับ |
|---|---|
| ผู้ดูแลระบบ (`isAdmin`) | `medsop.admin`, role `medsopAdmin`, role `admin` |
| ผู้จัดทำหน่วยงาน (`isAuthor`) | `medsop.author`, role `medsop` |
| ผู้ตรวจ (`canReview`) | `medsop.review`, role `director`, role `hr` |
| ดูทุกหน่วยงาน (`canViewAll`) | ระดับผู้ดูแล, ระดับผู้ตรวจ, `medsop.viewAll` |

**การมอบสิทธิ์:** หน้าจัดการผู้ใช้ → กำหนด role ให้ผู้ใช้
`medsop` = ผู้จัดทำของหน่วยงานที่ตนสังกัด, `medsopAdmin` = ผู้ดูแลระบบทั้งองค์กร

## ตัวกรองสิทธิ์ระดับ global (ต้องมี ไม่งั้นให้ role ไปก็ยัง 403)

แอปติดตั้ง `mdm\admin\components\AccessControl` เป็น `as access` ใน `config/web.php`
ซึ่งบังคับ **route permission** (`/medsop/*`) กับทุก request ก่อนถึง controller
โมดูลนี้ไม่ได้ใช้ route permission จึงต้องมี `'medsop/*'` อยู่ใน `allowActions`
เหมือนที่ `roster/*`, `task/*`, `service-profile/*` ทำ — ถอดออกเมื่อไหร่
ผู้ใช้ที่ไม่ใช่ `admin` (ซึ่งมี `/*`) จะเข้าโมดูลไม่ได้ทันที แม้จะมี role `medsop` แล้ว

เมนู "คลัง SOP/WI" ใน `themes/v4/layouts/navbar.php` แสดงตาม `canEnterModule()`
คือผู้ที่มีบทบาทใดบทบาทหนึ่งในโมดูล รวมหัวหน้าหน่วยงานที่ต้องเข้าหน้าสิทธิ์เข้าถึง
ผู้ใช้ทั่วไปที่เป็นแค่ผู้รับเอกสารยังไม่เห็นเมนูนี้

## ขอบเขตหน่วยงานของผู้จัดทำ

ยึดจาก `employees.department` ของผู้ใช้ที่ล็อกอิน — สร้างและแก้ไขได้เฉพาะเอกสาร
ที่ `medsop_document.organization_id` ตรงกับหน่วยงานนั้น ตัวเลือกหน่วยงานในฟอร์ม
ถูกกรองไว้แล้ว และฝั่งเซิร์ฟเวอร์ตรวจซ้ำอีกครั้งใน `saveForm()` กันการยัดค่ามาทาง POST

ผู้ใช้ที่ได้ role `medsop` แต่ยังไม่ผูกกับทะเบียนบุคลากร (ไม่มี `employees.user_id`)
หรือไม่มีหน่วยงานสังกัด จะสร้างเอกสารไม่ได้ ต้องผูกข้อมูลบุคลากรให้ครบก่อน

## Workflow เอกสาร

```
DRAFT ──ส่งอนุมัติ──▶ PENDING ──เผยแพร่──▶ PUBLISHED
  ▲                      │
  └──── REJECTED ◀───ส่งกลับแก้ไข (พร้อมเหตุผล)
```

- ผู้จัดทำหน่วยงานเดินได้ถึงขั้น `PENDING` เท่านั้น การเผยแพร่เป็นของผู้ดูแลระบบ
- ต้องกำหนดผู้รับเอกสารก่อนจึงส่งอนุมัติหรือเผยแพร่ได้
- `PENDING` แก้ไขไม่ได้ (ล็อกระหว่างรอตรวจ) ผู้ดูแลระบบส่งกลับก่อนจึงจะแก้ต่อได้
- เหตุผลที่ส่งกลับเก็บที่ `medsop_document.review_note` และแสดงบนหน้าเอกสาร
- `PUBLISHED` แก้ไขไม่ได้ (`Document::isEditable()` รับเฉพาะ `DRAFT`/`REJECTED`)

## สิทธิ์เข้าถึงข้ามหน่วยงาน

หน้า `/medsop/document/access` — หัวหน้าหน่วยงานเจ้าของเอกสารเปิดสิทธิ์ให้หน่วยงานอื่นเข้าดูเอง
ไม่ต้องผ่านผู้ดูแลระบบ ผู้ดูแลระบบทำแทนได้ทุกหน่วยงาน

- "หัวหน้าหน่วยงาน" อ่านจาก `tree.data_json.leader1` (รองรับคีย์ `leader_1` ด้วย)
  ผู้ช่วย/รองหัวหน้า (`leader2`) ไม่นับ — ถ้าต้องการให้นับด้วยต้องแก้ `leaderOrganizationIds()`
- สิทธิ์เก็บเป็นคู่หน่วยงานในตาราง `medsop_organization_access` บันทึกแบบแทนที่ทั้งชุด
- ครอบคลุมเฉพาะเอกสารที่ **เผยแพร่แล้ว** ฉบับร่างและเอกสารรออนุมัติยังเห็นได้เฉพาะภายในหน่วยงาน
- สิทธิ์นี้กว้างกว่ารายชื่อผู้รับ (audience) ที่ผูกกับเอกสารทีละฉบับ — เปิดครั้งเดียวครอบคลุมทั้งหน่วยงาน

การซ่อนปุ่มเป็นเพียง presentation ทุก action ต้องตรวจสิทธิ์ฝั่งเซิร์ฟเวอร์อีกครั้ง
