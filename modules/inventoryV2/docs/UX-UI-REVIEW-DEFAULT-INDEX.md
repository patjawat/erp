# รีวิว UX/UI: /inventory-v2/default/index

หน้านี้เป็น **Landing / เมนูนำทาง** ของโมดูลคลังสินค้า (ทั้ง `default/index` และ `default/navigation` ใช้ view เดียวกัน)

---

## 1. โครงสร้างหน้าปัจจุบัน

1. **Page title block** — ชื่อ "เมนูนำทางระบบ | ขั้นตอนการทำงานระบบคลังสินค้า" + ไอคอน
2. **เมนูแท็บ (action block)** — ปุ่มเมนูนำทาง, ภาพรวม, ทะเบียนรับเข้า, ทะเบียนขอเบิก, รายการจ่ายพัสดุ, ตั้งค่า
3. **แผนผัง Workflow** — การ์ดแสดง 5 ขั้น: จัดการพัสดุ → รับเข้าคลังหลัก → ขอเบิกจากคลังย่อย → จ่ายออกจากคลังหลัก → ตรวจสอบและรายงาน
4. **เมนูแยกตามส่วนงาน** — 4 การ์ด:
   - ส่วนจัดการข้อมูลพื้นฐาน (จัดการพัสดุ, ตั้งค่าคลัง)
   - ส่วนงานคลังหลัก (Dashboard, รับเข้า, สร้างใบรับเข้า, จ่ายออก, รายการใบขอเบิก)
   - ส่วนงานคลังย่อย (Dashboard, สร้างใบขอเบิก)
   - ส่วนรายงานและตรวจสอบ (Stock Card, รายงานคลังหลัก/ย่อย)
5. **ขั้นตอนการทำงานแบบละเอียด** — 5 ขั้นพร้อมรายการย่อยและลิงก์

---

## 2. จุดแข็ง

- **แบ่งบทบาทชัดเจน** — แยก "คลังหลัก" กับ "คลังย่อย" และ "ข้อมูลพื้นฐาน" กับ "รายงาน" ทำให้ผู้ใช้หาส่วนที่ตรงกับบทบาทได้ง่าย
- **มีแผนผังขั้นตอน** — เห็น flow รับเข้า → ขอเบิก → จ่าย อีกทั้งมีขั้นตอนแบบละเอียดพร้อมลิงก์ไปหน้าที่เกี่ยวข้อง
- **การ์ดลิงก์มี hover** — มี `translateX`, เปลี่ยน border/shadow ตอน hover บ่งบอกว่าเป็นลิงก์
- **Responsive** — ใช้ grid (col-md-6 col-lg-4), workflow และ step-item มี media query สำหรับมือถือ
- **ใช้ Bootstrap + Bootstrap Icons** — สอดคล้องกับโปรเจกต์ มี icon-wrapper และสีตามประเภท (info, success, warning, danger, primary, secondary)
- **สอดคล้องกับมาตรฐาน UI** — ไม่ใช้ card-body bg-light, ไม่ใช้ form-control-sm (หน้านี้ไม่มีฟอร์ม)

---

## 3. จุดที่ควรปรับปรุง

### 3.1 ความถูกต้องของ Flow และลิงก์

- **ขั้นที่ 4 (จ่ายออก):** ตอนนี้ระบบแยก "หัวหน้าอนุมัติ" กับ "คลังดำเนินการจ่าย" แล้ว แต่ข้อความใน workflow ยังเขียนว่า "คลังหลักอนุมัติและจ่ายพัสดุ" และในขั้นตอนแบบละเอียดมีลิงก์ไป **`/inventory-v2/issue/process` โดยไม่มี `id`** จึงใช้ไม่ได้
- **ข้อเสนอ:**  
  - อัปเดตข้อความขั้นที่ 4 เป็นประมาณ: "หัวหน้าอนุมัติใบขอเบิก → คลังดำเนินการจ่ายที่เมนู รายการจ่ายพัสดุ"  
  - ในขั้นตอนแบบละเอียด: เปลี่ยนลิงก์ "หน้าจ่าย" ให้ไป **รายการจ่ายพัสดุ** (`issue/index`) และอธิบายว่า "เลือกใบที่อนุมัติแล้ว แล้วกด ดำเนินการจ่าย"

### 3.2 Breadcrumb

- ปัจจุบันมีแค่ `$this->title` ขั้นเดียว
- **ข้อเสนอ:** เพิ่ม parent เช่น "คลังสินค้า" (ลิงก์ไป default/index หรือโมดูล) เพื่อให้สอดคล้องกับหน้าอื่น (เช่น main-stock/dashboard ที่มี "คลังสินค้า" → "Dashboard คลังหลัก")

### 3.3 ความยาวและลำดับความสำคัญ

- เนื้อหาค่อนข้างยาว: Workflow + 4 การ์ดเมนู + ขั้นตอนละเอียด 5 ขั้น
- **ข้อเสนอ:**  
  - พิจารณาใส่ **Quick actions** ด้านบน (ปุ่มใหญ่ 3–4 ปุ่ม): เช่น "รับเข้าคลัง", "สร้างใบขอเบิก", "รายการจ่ายพัสดุ", "Dashboard คลังหลัก" เพื่อลดการ scroll สำหรับผู้ใช้ที่ทำงานซ้ำ  
  - หรือย้าย "ขั้นตอนการทำงานแบบละเอียด" ไปเป็นอีกหน้า (เช่น "คู่มือการใช้งาน") แล้วใน index เหลือแค่ Workflow + เมนูแยกส่วนงาน

### 3.4 การเข้าถึง (Accessibility)

- ลิงก์ใน menu-link-card ใช้ทั้งบล็อกเป็น `<a>` — ดีสำหรับการคลิก
- **ข้อเสนอ:**  
  - เพิ่ม `:focus-visible` ใน style ของ `.menu-link-card` และ `.step-card` เพื่อให้ผู้ใช้คีย์บอร์ดเห็นจุดโฟกัสชัด  
  - ขั้นตอนแบบละเอียดอาจใช้ `<ol>` แทน `<div class="step-item">` เพื่อ semantics ที่ดีขึ้น

### 3.5 การใช้ชื่อหน้า Index vs Navigation

- `actionIndex()` และ `actionNavigation()` render view เดียวกัน แต่ชื่อหน้าที่ใช้คือ "เมนูนำทางระบบ..."
- **ข้อเสนอ:** ถ้า `/default/index` คือหน้าแรกของโมดูล อาจตั้ง title เป็น "คลังสินค้า" หรือ "ภาพรวมระบบคลัง" และใช้ "เมนูนำทางระบบ" เฉพาะเมื่อเข้าจาก `/default/navigation` (หรือรวมเป็นหน้าเดียวและใช้ title เดียวให้สอดคล้องกับเมนู)

## 4. สรุปข้อเสนอแนะ (ลำดับความสำคัญ)

| ลำดับ | รายการ | ประเภท |
|--------|--------|--------|
| 1 | แก้ลิงก์ "หน้าจ่าย" ในขั้นตอนที่ 4 ให้ไป `issue/index` และแก้คำอธิบายให้ตรงกับ flow จริง (อนุมัติแยกจากจ่าย) | แก้ผิด/ความสอดคล้อง |
| 2 | เพิ่ม breadcrumb ระดับบน (เช่น "คลังสินค้า") | ความสอดคล้องกับหน้าอื่น |
| 3 | พิจารณาเพิ่ม Quick actions ด้านบน (รับเข้า, สร้างใบขอเบิก, รายการจ่ายพัสดุ, Dashboard) | UX ลดการ scroll |
| 4 | เพิ่ม :focus-visible สำหรับลิงก์และการ์ด | Accessibility |
| 5 | พิจารณาย้าย "ขั้นตอนแบบละเอียด" ไปอีกหน้าหรือย่อลง (accordion) | ลดความยาวหน้า |

---

## 5. หมายเหตุเกี่ยวกับมาตรฐาน UI (.cursor/rules)

- หน้านี้ไม่มีตารางรายการ จึงไม่ใช้ `tbody align-middle table-group-divider`
- ไม่ใช้ `card-body bg-light` — ตรงกับกฎ
- ไม่มีฟอร์ม — ไม่เกี่ยวกับ form-control-sm / form-select
