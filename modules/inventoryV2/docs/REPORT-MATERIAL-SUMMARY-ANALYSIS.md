# วิเคราะห์รายงานสรุปรายงานวัสดุคงคลัง (ส่งบัญชี)

## 1. รายงานนี้ทำได้ไหม — **ได้**

รายงานในภาพเป็น **สรุปตามประเภทวัสดุ (หมวด M1, M2, M7, …)** ภายในช่วงเดือนที่เลือก มีคอลัมน์:

| คอลัมน์ในรายงาน | ความหมาย | แหล่งข้อมูลในระบบ |
|-----------------|----------|---------------------|
| **รายการ** | ประเภทวัสดุ เช่น (M1)วัสดุสำนักงาน | `stock_item.category_id` → `categorise` (asset_type), แสดงเป็น code + title |
| **สินค้าคงเหลือ** | ยอดต้นงวด | ยอดยกมา / opening ของงวด |
| **ซื้อระหว่างเดือน** | รับเข้าในงวด | รวมรายการ IN (รับเข้า) ในช่วงนั้น |
| **รวม** | สินค้าคงเหลือ + ซื้อระหว่างเดือน | คำนวณได้ |
| **สินค้าที่ใช้ไป** | | |
| ↳ จ่ายส่วนของ รพ.สต. | จ่ายตามหน่วยงาน/ต้นทุนหนึ่ง | แยกตามกฎ (ดูด้านล่าง) |
| ↳ จ่ายส่วนของโรงพยาบาล | จ่ายตามหน่วยงาน/ต้นทุนอีกกลุ่ม | แยกตามกฎ |
| ↳ รวม | รวมจ่ายทั้งหมด | รวม 2 ช่องบน |
| **ยอดยกไป** | ยอดปลายงวด | รวม − รวมจ่าย (หรือใช้ closing โดยตรงถ้ามี) |

ระบบมี:

- **stock_order** + **stock_detail**: รับเข้า (IN) / จ่ายออก (OUT) ต่อรายการ พร้อมวันที่ คลัง หน่วยงานปลายทาง (sub_warehouse_id)
- **stock_item**: แต่ละรายการมี `category_id` เชื่อมกับประเภทวัสดุ (M1, M2, …)
- **stock_balance**: ยอดคงเหลือปัจจุบันต่อคลัง/Lot
- **stock_monthly_report** (มีตารางแล้ว): เก็บยอดราย**รายการ (item)** ต่อเดือน อยู่แล้ว มีฟิลด์ `out_sub_qty` และ `out_hosp_qty` สำหรับแยก “จ่ายส่วนของ รพ.สต.” กับ “จ่ายส่วนของโรงพยาบาล”

ดังนั้น **สามารถทำรายงานนี้ได้** โดย:

1. นำ transaction (รับ/จ่าย) มาคำนวณหรืออ่านจาก `stock_monthly_report` ที่ระดับ **รายการ (item)**
2. รวมตาม **ประเภทวัสดุ (category)** ผ่าน `stock_item.category_id` → แสดงเป็นแถวรายการ (M1), (M2), …
3. แยกยอดจ่ายเป็น 2 กลุ่ม (รพ.สต. / โรงพยาบาล) ตามกฎที่กำหนด (เช่น ตามหน่วยงานที่รับของ)

## 2. ต้องสร้างตารางเก็บยอดของแต่ละ (เดือน) ไหม — **มีอยู่แล้ว + เลือกได้**

### 2.1 ตารางที่ **มีอยู่แล้ว**: `stock_monthly_report`

ใน migration มีตาราง **stock_monthly_report** อยู่แล้ว สำหรับเก็บยอดต่อ **รายการ (item)** ต่อเดือน:

- `report_year`, `report_month`, `warehouse_id`, `item_code`
- `opening_qty`, `opening_value` — สินค้าคงเหลือต้นงวด
- `in_qty`, `in_value` — ซื้อ/รับระหว่างเดือน
- `out_sub_qty` — จ่ายส่วนของ รพ.สต. (หรือตามที่กำหนด)
- `out_hosp_qty` — จ่ายส่วนของโรงพยาบาล
- `total_out_qty`, `total_out_value`
- `closing_qty`, `closing_value` — ยอดยกไป

ดังนั้น **ไม่จำเป็นต้องสร้างตารางใหม่** สำหรับเก็บยอดระดับรายการต่อเดือน ถ้าใช้ตารางนี้เป็นหลัก。

### 2.2 ระดับ “รายการ” vs “ประเภทวัสดุ”

- **stock_monthly_report** เก็บที่ระดับ **รายการ (item_code)**  
  → รายงานส่งบัญชีเป็น **สรุปตามประเภท (M1, M2, …)** จึงต้อง **รวม (SUM) จากรายการในประเภทเดียวกัน** ในตอนสร้างรายงาน
- ถ้าต้องการ **ไม่คำนวณจาก transaction ทุกครั้ง** ให้:
  - **ตัวเลือก A (แนะนำขั้นต่ำ):** ใช้ตาราง `stock_monthly_report` ที่มีอยู่ → สร้าง job ปิดเดือนเติมข้อมูลรายการ → เวลาแสดงรายงานแค่ GROUP BY category แล้ว SUM
  - **ตัวเลือก B (ถ้าต้องการเร็วมาก):** สร้างตารางเพิ่ม เช่น `stock_monthly_report_by_category` เก็บยอดรวมต่อประเภทต่อเดือน (เปิด/รับ/จ่ายรพ.สต./จ่ายโรงพยาบาล/ปิด) แล้วให้ job ปิดเดือนคำนวณจาก `stock_monthly_report` หรือจาก transaction มาเติมตารางนี้ — **ไม่จำเป็นต้องมีในเฟสแรก** ถ้ายังไม่มีปัญหาเรื่องความเร็ว

สรุปคำถาม “ต้องสร้างตารางเก็บยอดของแต่ละได้ไหม”:

- **เก็บยอดรายการต่อเดือน:** ไม่ต้องสร้างใหม่ มี `stock_monthly_report` แล้ว
- **เก็บยอดประเภทต่อเดือน:** ไม่บังคับในเฟสแรก; ทำได้โดยรวมจาก `stock_monthly_report` + `stock_item.category_id` ก่อน แล้วค่อยเพิ่มตารางสรุปประเภทถ้าต้องการในภายหลัง

## 3. สิ่งที่ต้องทำในระบบ

1. **โมเดลและ logic สำหรับรายงาน**
   - สร้าง/ใช้โมเดลอ่าน `stock_monthly_report` (และถ้ามี `stock_monthly_report_by_category` ในอนาคต)
   - คำนวณหรือดึงยอดรายการต่อเดือน แล้ว **รวมตาม category_id** (ผ่าน `stock_item` + `categorise`) ให้ได้แถวรายงานแบบ (M1), (M2), …
   - คอลัมน์: สินค้าคงเหลือ, ซื้อระหว่างเดือน, รวม, จ่าย รพ.สต., จ่ายโรงพยาบาล, รวมจ่าย, ยอดยกไป

2. **กฎแยก “จ่ายส่วนของ รพ.สต.” vs “จ่ายส่วนของโรงพยาบาล”**
   - ตารางมี `out_sub_qty` / `out_hosp_qty` อยู่แล้ว แต่ระบบต้องมีกฎว่าแต่ละรายการจ่าย (OUT) นับเป็น “รพ.สต.” หรือ “โรงพยาบาล”
   - ตัวอย่างแนวทาง:
     - ใช้ **หน่วยงานที่รับของ (sub_warehouse_id)** แล้ว map ว่า warehouse/แผนกไหนนับเป็น “รพ.สต.” ที่เหลือเป็น “โรงพยาบาล”
     - หรือเก็บใน `stock_order.data_json` / ฟิลด์อื่นว่าใบจ่ายนี้เป็นประเภทไหน
   - ต้องให้ทีมบัญชี/คลังกำหนดกฎแล้ว implement ตรงจุดที่บันทึก/ปิดเดือน

3. **การเติมข้อมูล `stock_monthly_report`**
   - ตอนนี้มีแค่โครงตาราง ยังไม่มีโมเดล/ไม่มี job เติมข้อมูล
   - ต้องมีกระบวนการ **ปิดเดือน**: อ่านจาก `stock_order` + `stock_detail` (และ stock_balance ถ้าต้องการยอดเปิด/ปิด) แล้วคำนวณ opening, in, out_sub, out_hosp, closing ต่อรายการต่อเดือน แล้ว INSERT/UPDATE ลง `stock_monthly_report`
   - ทำเป็น batch ทุกสิ้นเดือน หรือรันเมื่อกด “สร้างรายงานเดือน X” ก็ได้

4. **หน้า UI รายงาน**
   - ฟิลเตอร์: วันที่เริ่ม–สิ้นสุด (หรือเลือกเดือน)
   - ปุ่มค้นหา / Export Excel ตามที่ในภาพ
   - ตาราง: แถวต่อประเภทวัสดุ (จาก categorise) แสดงทุกคอลัมน์ตามรายงาน + แถวรวม (สีเหลือง)
   - ใช้เฉพาะ class Bootstrap 5 ไม่ใช้ `small` ตามที่กำหนด

## 4. สรุปสั้นๆ

| คำถาม | คำตอบ |
|--------|--------|
| จะช่วยทำรายงานนี้ได้ไหม | **ได้** — โครงข้อมูลและตารางรองรับแล้ว แค่เพิ่ม logic รวมตามประเภท + กฎแยกจ่าย + หน้าแสดง/Export |
| ต้องสร้างตารางเก็บยอดของแต่ละเดือนไหม | **ไม่ต้องสร้างใหม่** สำหรับยอดรายการ — มี `stock_monthly_report` แล้ว; เก็บยอดประเภทต่อเดือนเป็นตัวเลือกเพิ่มถ้าต้องการความเร็ว |

## 5. การตั้งค่า "จ่ายส่วนของ รพ.สต." vs "จ่ายส่วนของโรงพยาบาล"

ใน `config/params.php` (หรือที่กำหนด params ของแอป) สามารถกำหนดรายการ ID คลังย่อยที่ถือเป็น **จ่ายส่วนของ รพ.สต.** ได้:

```php
'params' => [
    // รหัสคลังย่อย (sub_warehouse_id) ที่เมื่อใบจ่ายส่งไปที่นี้นับเป็น "จ่ายส่วนของ รพ.สต." ที่เหลือนับเป็น "จ่ายส่วนของโรงพยาบาล"
    'inventoryV2.disburseSubWarehouseIds' => [1, 2],
],
```

ถ้าไม่กำหนด หรือใบจ่ายมี sub_warehouse_id ไม่อยู่ในรายการ ยอดจะไปอยู่ในคอลัมน์ "จ่ายส่วนของโรงพยาบาล"
