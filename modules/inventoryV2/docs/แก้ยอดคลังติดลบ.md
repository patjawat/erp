# แก้ยอดคลังติดลบ และการล้างคลังเพื่อทดสอบ

## สาเหตุที่ยอดอาจติดลบ

- **ข้อมูลเก่า / นำเข้าจากระบบอื่น** ที่หักยอดโดยไม่ผ่าน flow ปัจจุบัน
- **รายงานสรุป (สรุปรายงานวัสดุคงคลัง)** คำนวณจาก `stock_monthly_report` (ปิดเดือน): ยอดยกไป = เปิด + รับ - จ่าย ถ้าข้อมูลเปิด/รับ/จ่ายไม่ตรงกับความจริง จะได้ยอดติดลบในรายงาน
- ใน **stock_balance** ระบบพยายามกันไม่ให้ติดลบตอนจ่าย (หัก) ผ่าน `InventoryService::updateBalance` — ถ้ายังมีจุดอื่นหักยอดโดยตรงอาจทำให้ติดลบได้

---

## วิธีแก้ยอดติดลบ

### 1. ใช้เมนู **ปรับยอด stock** (แนะนำ)

- ไปที่ **คลังสินค้า → ปรับยอด stock** (`/inventory-v2/stock-adjust`)
- เลือก **คลัง** และ **รหัสพัสดุ** ที่ติดลบ (หรือประเภทที่รวมแล้วติดลบ ให้ปรับทีละรหัสที่เกี่ยวข้อง)
- กด **ดึงยอดคงเหลือ** เพื่อดูยอดปัจจุบัน
- ใส่ **จำนวนที่ปรับ** เป็น **เลขบวก** เพื่อชดเชยยอดที่ขาด  
  - ตัวอย่าง: รายงานแสดงยอดยกไป -9 → ปรับ **+9** ให้พัสดุนั้นในคลังนั้น
- บันทึกการปรับยอด

หลังแก้ **stock_balance** แล้ว ถ้ารายงานสรุปใช้ข้อมูลจาก **ปิดเดือน** ให้ไปที่ **สรุปรายงานวัสดุคงคลัง** แล้วกด **ปิดเดือน** ใหม่สำหรับเดือนที่แก้ เพื่อให้ตัวเลขในรายงานสรุปตรงกับยอดจริงอีกครั้ง

### 2. ตรวจสอบว่ายอดติดลบอยู่ที่ไหน

- **ยอดติดลบในหน้ายอดคงเหลือตามคลัง** → แก้ที่ **stock_balance** ด้วยเมนูปรับยอด (ตามข้อ 1)
- **ยอดติดลบในรายงานสรุป (สรุปรายงานวัสดุคงคลัง)** → แก้ยอดจริงใน stock_balance ก่อน แล้ว **ปิดเดือนใหม่** เพื่อให้รายงานสรุปคำนวณใหม่

## ล้างยอดคลังเพื่อทดสอบระบบใหม่

ถ้าต้องการ **เคลียร์ยอดคลังเพื่อทดสอบ flow ตั้งแต่ต้น**:

- ใช้เมนู **ปรับยอด stock** แล้วกดปุ่ม **ล้างยอดคลัง (สำหรับทดสอบ)** หรือไปที่ `/inventory-v2/stock-adjust/reset-warehouse`
  - เลือกคลังที่ต้องการล้าง (เฉพาะคลังหลัก)
  - พิมพ์คำว่า **ล้าง** ในช่องยืนยัน แล้วกดล้าง — ระบบจะตั้ง **ยอดคงเหลือ (stock_balance)** ในคลังนั้นเป็น **0** ทุกรายการ
  - มีขั้นตอนยืนยันเพื่อลดความเสี่ยงล้างผิดคลัง

**หมายเหตุ:** การล้างยอดไม่ลบเอกสารรับ/จ่าย (stock_order, stock_detail) — เหลือเพียงยอดคงเหลือในคลังเป็น 0 เพื่อให้ลองรับเข้า/จ่ายใหม่ได้จากศูนย์

## ล้างตารางทั้งหมด (TRUNCATE) — แก้ error #1701 Foreign Key

ถ้ารัน `TRUNCATE TABLE stock_order` (หรือตารางอื่นที่ถูกอ้างอิงด้วย FK) แล้วเจอ:

```text
#1701 - Cannot truncate a table referenced in a foreign key constraint (`dansai`.`stock_detail`, CONSTRAINT `fk_stock_detail_order`)
```

**สาเหตุ:** ตาราง `stock_detail` มี FK ชี้ไปที่ `stock_order` MySQL จึงไม่ให้ TRUNCATE ตารางที่ถูกอ้างอิงโดยตรง

**วิธีแก้ (เลือกอย่างใดอย่างหนึ่ง):**

### วิธีที่ 1: ล้างตามลำดับ (ลูกก่อน แม่หลัง)

รัน SQL ตามลำดับนี้ (ใน phpMyAdmin หรือ client อื่น):

```sql
-- ลบรายละเอียดก่อน (ลูก)
TRUNCATE TABLE stock_detail;

-- จากนั้นลบหัวเอกสาร (แม่)
TRUNCATE TABLE stock_order;

-- ถ้าต้องการล้างยอดคงเหลือและรายงานด้วย
TRUNCATE TABLE stock_balance;
TRUNCATE TABLE stock_monthly_report;
```

### วิธีที่ 2: ปิดการตรวจสอบ FK ชั่วคราว

รันเป็นชุดเดียว (ใช้เฉพาะเมื่อต้องการล้างหลายตารางพร้อมกัน):

```sql
SET FOREIGN_KEY_CHECKS = 0;

TRUNCATE TABLE stock_detail;
TRUNCATE TABLE stock_order;
TRUNCATE TABLE stock_balance;
TRUNCATE TABLE stock_monthly_report;

SET FOREIGN_KEY_CHECKS = 1;
```

**คำเตือน:** การล้างตารางจะลบข้อมูลทั้งหมดในตารางนั้น — ใช้เฉพาะในสภาพแวดล้อมทดสอบหรือเมื่อต้องการ reset ข้อมูลคลังทั้งชุด
