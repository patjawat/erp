# แผนพัฒนาทะเบียนคุมงานการเงิน (Financial Control Registries)

> เอกสารสเปก/แผนพัฒนา — เวอร์ชันแรก 2026-09-22
> ขอบเขต: ทะเบียนคุม 18 รายการ 5 หมวด ที่งานการเงิน รพ. ต้องจัดทำ เทียบกับสิ่งที่มีในระบบ ERP แล้ววางแผนพัฒนาส่วนที่ขาด
> เอกสารนี้ยังไม่แตะโค้ด/ฐานข้อมูล — เป็นสเปกให้เคาะก่อนลงมือ

## 0. หลักคิดสถาปัตยกรรม (อ่านก่อน)

ทะเบียนคุมส่วนใหญ่ **ไม่ใช่ "ชุดข้อมูลใหม่" แต่คือ "รายงานรูปแบบทะเบียน" (running-balance register)** ที่ฉายจากธุรกรรมที่ระบบบันทึกอยู่แล้ว งานจริงแยก 3 ชนิด:

| ชนิด | ความหมาย | ตัวอย่าง | ต้นทุน |
|---|---|---|---|
| **A** | มีข้อมูลต้นทางแล้ว ขาดแค่ "หน้าทะเบียน" มาตรฐาน | เงินบำรุง, เจ้าหนี้, เช็ค, หลักประกัน | ต่ำ |
| **B** | มีบางส่วน ต้องต่อยอด/เพิ่มมิติ (field/tag) | เงินฝาก reconcile, WHT, ฎีกา, เงินสดย่อย, โครงการ | กลาง |
| **C** | ยังไม่มี subsystem ต้นทางเลย | AR ลูกหนี้ค่ารักษา, เงินมัดจำ, เงินงบประมาณทั้งหมวด | สูง |

**หลักการออกแบบ:** สร้าง Register report layer กลาง 1 ชุด ให้ทะเบียนทุกเล่มใช้ฟอร์แมต/พิมพ์/Excel ร่วมกัน — ไม่เขียนหน้ารายงานซ้ำต่อเล่ม

## 2. เฟส 0 — Register Layer (ชั้นรายงานทะเบียนคุมกลาง)

**เป้าหมาย:** engine เดียว ปล่อยทะเบียนชนิด A ได้ทันทีจากข้อมูลเดิม (2.1, 2.2, 4.2, 4.3, 5.2)

**ฟอร์แมตทะเบียนมาตรฐาน (คอลัมน์):**
`ลำดับ | วันที่ | เลขที่เอกสาร | รายการ | เดบิต/รับ | เครดิต/จ่าย | คงเหลือ (running) | อ้างอิง | หมายเหตุ`

**การออกแบบ (config-driven, ไม่ผูกตารางใดตารางหนึ่ง):**
- `FinanceRegisterService` รับ "นิยามทะเบียน" (registry definition) = { source model/query, filter, mapping คอลัมน์→รับ/จ่าย, กลุ่มยอดยกมา } แล้วคืน rows พร้อม running balance + ยอดยกมา/ยกไป
- `RegisterController` + view เดียว: แสดงผล + พิมพ์ (เบราว์เซอร์/PDF) + Excel export
- นิยามทะเบียนเก็บเป็น config array ก่อน (เร็ว) — ยกระดับเป็นตาราง `finance_register_def` ภายหลังถ้าต้องให้ผู้ใช้เพิ่มเอง
- เมนู: pill "ทะเบียนคุม" ใต้ `/finance` รวมทุกเล่มไว้ที่เดียว

**Deliverable เฟส 0:** ทะเบียน 5 เล่มพิมพ์ได้ตรงฟอร์แมต ITA/สตง./HA จากข้อมูลที่มีอยู่ (ไม่มี migration ใหม่)

## 3. เฟส 1 — ปิดช่องฝั่ง AP / ภาษี (ต่อยอดของเดิม)

### 3.1 ทะเบียนฎีกา/ใบสำคัญขอเบิก (4.1)
- ต่อยอด [[finance-ap-inbox-flow]]: เพิ่ม "เลขฎีกา" รันต่อเนื่องรายปีงบเมื่อรับเรื่องเข้า/อนุมัติจ่าย
- ทางเลือก: เพิ่มคอลัมน์เลขฎีกา + สถานะคิวบน `finance_inbox`/`finance_payable` แล้วฉายผ่าน Register Layer (ไม่ต้องตารางใหม่)

### 3.2 ทะเบียน WHT + สรุปนำส่ง ภงด. (5.1)
- รวม field WHT ที่กระจายบน `finance_payable_payment` / `finance_cash_voucher` / `finance_voucher` เป็น register เดียว
- เพิ่มมุมมองสรุปรายเดือนแยกประเภท ภงด.1 / 3 / 53 (ยอดฐาน, ภาษี, ผู้ถูกหัก) เพื่อกระทบยอดก่อนนำส่งสรรพากรวันที่ 7
- อาจต้องตารางเบา `finance_wht_entry` (denormalize จากจุดจ่าย) เพื่อออกหนังสือรับรองหัก ณ ที่จ่าย — เคาะภายหลัง

### 3.3 เงินทดรองจ่าย / เงินสดย่อย (4.4) — แยกจากเงินยืม
- กลไก imprest (วงเงินหมุนเวียนคงที่ เบิกชดเชยเมื่อใช้) ต่างจากเงินยืมรายสัญญา ([[finance-loan-module]]) — ต้องแยก
- ตารางใหม่: `finance_petty_cash` (วงเงิน/ผู้รับผิดชอบ/จุดบริการ) + `finance_petty_cash_txn` (จ่ายย่อย/ชดเชย) → ฉายเป็นทะเบียนผ่าน Register Layer

## 4. เฟส 2 — AR ลูกหนี้ค่ารักษา (จุดยุทธศาสตร์ ต่อ liquidity)

**แหล่งข้อมูล: นำเข้าจาก HIS / ระบบเคลม (ยืนยันแล้ว)** — ไม่คีย์รายวิสิต แต่ import ยอดลูกหนี้แยกสิทธิ

เชื่อมโดยตรงกับ [[liquidity-monitor-project]] — AR คือ input หลักของการพยากรณ์เงินเข้า

**ตารางที่เสนอ:**
- `finance_ar_fund` — master สิทธิ (UC/บัตรทอง, ประกันสังคม, พรบ.รถ, ข้าราชการจ่ายตรง, เงินสด/ชำระเอง, อื่น ๆ) + รอบเรียกเก็บ/เงื่อนไข
- `finance_ar_invoice` — ลูกหนี้รายก้อน: งวด/เดือน, สิทธิ (fund_id), ยอดตั้งเบิก, ยอดได้รับจริง, ส่วนต่าง, สถานะ (ตั้งลูกหนี้/ส่งเคลม/รับชำระบางส่วน/ตัดหนี้สูญ), อ้างอิงแหล่ง
- `finance_ar_settlement` — การรับชำระ/ตัดจ่าย/ปรับปรุง (partial receipt, เคลมคืน, adjust)
- `finance_ar_import_batch` — ชุดนำเข้าจาก HIS/e-Claim/NHSO (ไฟล์, งวด, ผู้ import, สรุปยอด)
- `finance_patient_deposit` — เงินมัดจำ/รับฝากผู้ป่วย (3.3): รับฝาก → หักชำระ → คืน

**Deliverable:**
- 3.1 ทะเบียนลูกหนี้แยกสิทธิ (register + สรุปยอดคงค้างแต่ละสิทธิ + aging)
- 3.2 ทะเบียนรายได้ค้างรับ = view สถานะ unpaid/partial (ไม่ตารางใหม่)
- 3.3 ทะเบียนเงินมัดจำ/รับฝาก

**ต้องเคาะก่อนลงมือ:** รูปแบบไฟล์/สิทธิที่ HIS ส่งออกได้ (คอลัมน์, ความถี่, มี e-Claim/NHSO REP หรือไม่) → กำหนด mapping การ import

## 5. เฟส 3 — เงินฝาก reconcile + โครงการ (ต่อยอดหมวด 2)

- **2.3 งบพิสูจน์ยอดเงินฝากธนาคาร:** ตาราง `finance_bank_reconcile` (รายเดือน/รายบัญชี: ยอดตามบัญชี รพ. vs ยอดตาม statement + รายการกระทบยอด เช็คค้างจ่าย/เงินระหว่างทาง) — ต่อจาก `finance_cash_account`
- **2.4 จำแนกตามโครงการ:** เพิ่ม `project_id` (หรือ tag) ที่ระดับ `finance_cash_txn` → ฉายทะเบียนแยกโครงการผ่าน Register Layer เชื่อม [[annual-plan-move-to-plan-module]]

## 6. เฟส 4 — เงินงบประมาณ (ทำครบหมวด 1 — ยืนยันแล้ว)

รพ. บริหารเงินงบประมาณเอง → ทำครบทั้ง 5 ทะเบียน ออกแบบเป็น sub-module `finance/budget` ขนานกับ `finance/cash`

**ตารางที่เสนอ (ลีนแบบเดียวกับ cash module):**
- `finance_budget_allotment` — เงินประจำงวด (1.1): งวด, งบรายจ่าย (บุคลากร/ดำเนินงาน/ลงทุน/อุดหนุน/รายจ่ายอื่น), ยอดจัดสรร, ยอดคงเหลือ
- `finance_budget_txn` — รับ-จ่ายเงินงบประมาณ (1.2): direction (รับจากคลัง/จ่าย), allotment_id, งบรายจ่าย, ยอด, เลขเอกสาร → ครอบ 1.2 และเป็นฐานของ 1.5 ผ่านหมวดงบกลาง
- `finance_treasury_remit` — รับและนำส่งเงิน นส.02 (1.3): ประเภทรายได้แผ่นดิน, ยอดจัดเก็บ, วันนำส่ง, เลข นส.02
- `finance_budget_return` — เบิกเกินส่งคืนคลัง (1.4): อ้าง txn เบิก, ยอดคงเหลือ/ส่งคืน, วันส่งคืน
- **งบกลาง/สวัสดิการ (1.5):** เป็น "หมวดงบรายจ่าย" ภายใน `finance_budget_txn` (ค่ารักษา ขรก. / ช่วยเหลือบุตร / การศึกษาบุตร) + register แยกหมวด — ไม่ต้องตารางแยก

ทั้ง 5 ทะเบียนฉายออกผ่าน Register Layer เดียวกัน

## 8. จุดที่ต้องเคาะก่อนเริ่มเขียนโค้ด
