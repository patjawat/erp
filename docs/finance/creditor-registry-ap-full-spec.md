## 0. สรุปสำหรับผู้บริหาร/ผู้ตัดสินใจ

ระบบวงจรเจ้าหนี้เต็มรูปแบบ = **6 ช่วง**: `จัดซื้อ → บัญชีตั้งหนี้ → รับวางบิล → ขออนุมัติจ่าย → จ่าย/พิมพ์เช็ค → ตัดจ่าย+รายงาน`

Codex ทำ **ช่วงที่ 1–2 เสร็จแล้ว** (จัดซื้อส่งบัญชี → Inbox → รับรอง → ร่างทะเบียน → อนุมัติเข้าทะเบียน)
เอกสารนี้เติม **ช่วงที่ 3–6 + การนำเข้า Excel** ซึ่งเป็นสิ่งที่ยังขาดและเป็นความต้องการหลักของงานนี้

> ⚠️ **ข้อควรระวังการแบ่งงาน:** โมดูล `accounting` และ `finance/payable|voucher|payment` เป็นพื้นที่ของ Codex เอกสารนี้จึงเป็นสเปกเพื่อ **ส่งมอบ/ประสาน** ไม่ใช่ให้ลงมือแทน

### ❌ ยังไม่มี (ช่องว่างที่เอกสารนี้เติม)

1. **นำเข้า Excel** — มี `source_type = payable_import` ระบุไว้ในตาราง mapping แต่ยังไม่มีตัวนำเข้า/template/หน้าตรวจ
2. **บันทึกรับวางบิล** เป็นขั้น workflow แยก (ปัจจุบัน `billing_date` กรอกตอนตั้งหนี้ล่วงหน้าเท่านั้น)
3. **ขออนุมัติจ่าย / ฎีกา (voucher)** — `FinanceVoucher` มีแต่ยัง draft "ยังไม่มีการอนุมัติหรือจ่ายเงินจริง"
4. **แผนจ่าย + พิมพ์เช็ค + ตัดจ่าย (settlement)**
5. **หนังสือรับรองหัก ณ ที่จ่าย (WHT cert) + ภ.ง.ด.**
6. **รายงาน**: ยอดคงเหลือรายเจ้าหนี้, aging, กระทบยอด GL, สถานะเจ้าหนี้

## 2. พื้นฐานบัญชีเจ้าหนี้ที่ต้องยึด (เกณฑ์คงค้าง ภาครัฐ)

### 2.1 ทะเบียนคุมเจ้าหนี้ = Subsidiary Ledger
- เป็นบัญชีย่อยรายผู้ขาย ที่ **ต้องกระทบยอด (reconcile) กับบัญชีคุมยอด "เจ้าหนี้การค้า" ใน GL** เสมอ
  `Σ ยอดคงเหลือทุกเจ้าหนี้ในทะเบียน = ยอดบัญชีเจ้าหนี้การค้าใน GL`
- ยอดคงเหลือรายตัว = **ยอดยกมา + ตั้งหนี้ − ตัดจ่าย**

### 2.2 รับรู้ตามเกณฑ์คงค้าง (accrual) — จุดตั้งหนี้คือ "ตรวจรับ" ไม่ใช่ "จ่าย"

| เหตุการณ์ | รายการบัญชี (แนวคิด) |
|---|---|
| **ตั้งหนี้** (ตรวจรับของ/งานเสร็จ) | Dr. พัสดุคงคลัง/ค่าใช้จ่าย/สินทรัพย์ · **Cr. เจ้าหนี้การค้า** |
| **ตัดจ่าย** (จ่ายเงินจริง) | Dr. เจ้าหนี้การค้า · Cr. ภาษีหัก ณ ที่จ่ายค้างจ่าย · **Cr. เงินฝากธนาคาร** |
| นำส่ง WHT | Dr. ภาษีหัก ณ ที่จ่ายค้างจ่าย · Cr. เงินฝากธนาคาร |

> ระยะแรกระบบยัง **ไม่ post GL อัตโนมัติ** (ตาม shadow-mode ของ Codex) — เก็บเป็นทะเบียน/ข้อมูลก่อน แล้วออกรายงานให้บัญชีบันทึกเข้าระบบบัญชีจริง (GL/GFMIS) — ตรงนี้เป็นจุดตัดสินใจใน §11

### 2.3 ภาษีหัก ณ ที่จ่าย (WHT)
- หักตอน **จ่าย** ไม่ใช่ตอนตั้งหนี้ → `net_amount = gross − WHT` (VAT แยกเก็บ)
- อัตราแล้วแต่ประเภท (จ้างบริการ 3%, ค่าเช่า 5%, จ้างทำของ ฯลฯ) — **อัตราจริงรอการเงินยืนยัน** (ดู note ในบันทึกงานพัสดุ)
- ต้องออก **หนังสือรับรองหัก ณ ที่จ่าย** ต่อการจ่าย และสรุป **ภ.ง.ด.3/53** รายเดือน

## 3. Flow end-to-end + วงจรชีวิตสถานะ

```
ช่วง 1: จัดซื้อ            ช่วง 2: บัญชี                   ช่วง 3-6: การเงิน
────────────           ─────────────────           ────────────────────────
PO → ตรวจรับ(GR)                                    
   │ กด "ส่งบัญชี"                                    
   ▼                                                
[Inbox] pending_review                              
   │ 3-way match: PO↔GR↔Invoice, WHT, ผังบัญชี      
   ▼ accepted                                       
[ทะเบียน] draft → pending_approval → approved ──────▶ (ตั้งหนี้เสร็จ)
                                                        │
                                              ┌─────────┘
                                              ▼ ช่วง 3
                                        รับวางบิล (bill_received)
                                        บันทึกวันรับบิล + due จริง + แนบบิล
                                              │
                                              ▼ ช่วง 4
                                        รวมใบครบกำหนด → ฎีกา/ขออนุมัติจ่าย
                                        (voucher: draft → submitted → approved)
                                              │
                                              ▼ ช่วง 5
                                        จ่าย/พิมพ์เช็ค (paid)
                                        + หนังสือรับรอง WHT
                                              │
                                              ▼ ช่วง 6
                                        ตัดจ่ายในทะเบียน (settled)
                                        + รายงาน aging / reconcile GL
```

### 3.1 สถานะเจ้าหนี้แบบเต็มวงจร (เสนอ)

แยก 2 มิติเพื่อไม่ปนกัน (ปัจจุบัน `status` ปนเฉพาะขั้นตั้งทะเบียน):

- **`register_status`** (มีแล้ว): `draft → pending_approval → needs_revision → approved`
- **`payable_status`** (เสนอเพิ่ม สำหรับใบที่ `approved` แล้ว):

| payable_status | ความหมาย | ยอดในทะเบียน |
|---|---|---|
| `outstanding` | ตั้งหนี้แล้ว รอวางบิล/รอจ่าย | เป็นหนี้คงค้าง |
| `bill_received` | รับวางบิลแล้ว มี due จริง | คงค้าง (เข้าคิวจ่าย) |
| `in_voucher` | อยู่ในฎีกาขออนุมัติจ่าย | คงค้าง (ล็อกไม่ให้ซ้ำฎีกา) |
| `approved_to_pay` | อนุมัติจ่ายแล้ว รอออกเช็ค | คงค้าง |
| `paid` | จ่าย/พิมพ์เช็คแล้ว | รอตัดจ่าย |
| `settled` | ตัดจ่ายในทะเบียนแล้ว | **0 (ปิดหนี้)** |
| `partially_settled` | จ่ายบางส่วน | คงเหลือ = หนี้ − ที่จ่าย |
| `void` | ยกเลิก/ตั้งหนี้ผิด | ไม่นับ |

> เก็บ `payable_status` แยก ทำให้ **รายงานสถานะเจ้าหนี้/aging ตรงตามมาตรฐาน** และกันการจ่ายซ้ำด้วยการเช็คสถานะขณะ update (optimistic lock แบบเดียวกับ maker-checker เดิม)

## 5. ช่วง 3 — บันทึกรับวางบิล (bill receipt)

> ในทางปฏิบัติ ผู้ขายมาวางบิลเป็นรอบ **หลัง** ตั้งหนี้ → `billing_date` ตอนตั้งหนี้อาจเป็นค่าประมาณ ต้องมีขั้นบันทึกรับบิลจริง

- เมนู "รับวางบิล" (role `financeOfficer`) — ลิสต์ใบ `outstanding` ที่ยังไม่รับบิล
- ฟอร์ม: **วันรับวางบิลจริง**, เลขที่บิล/ใบส่งของ, แนบไฟล์บิล, ยืนยัน/แก้ due จริง (billing + credit_days), ผู้รับบิล
- ออก **ใบรับวางบิล** (เลขที่รับบิล, พิมพ์ได้) → เปลี่ยน `payable_status = bill_received`
- รองรับ **1 บิล = หลายใบตั้งหนี้** (ผู้ขายรวมหลาย invoice มาวางครั้งเดียว) → ตาราง `bill_receipt` + `bill_receipt_item`

## 6. ช่วง 4–5 — ขออนุมัติจ่าย + ฎีกา + พิมพ์เช็ค

### 6.1 แผน/รวมรายการจ่าย
- เลือกใบ `bill_received` ที่ครบกำหนด (กรองตาม due/แหล่งเงิน/ผู้ขาย) → รวมเป็น **ฎีกา (voucher)** 1 ใบต่อผู้ขาย/งวด
- ต่อยอด `FinanceVoucher` เดิม: `draft → submitted → approved → paid` (maker-checker เหมือนทะเบียน)
- ล็อกใบที่อยู่ในฎีกา = `in_voucher` กันรวมซ้ำ

### 6.2 อนุมัติจ่าย
- `financeApprover` อนุมัติ → `approved_to_pay`; ผู้จัดทำฎีกาอนุมัติเองไม่ได้

### 6.3 พิมพ์เช็ค/โอน (⚠️ ไม่ใช่การจ่ายเงินจริงในระบบ)
- ระบบ **พิมพ์เอกสาร** (เช็ค/ใบสำคัญจ่าย/ใบรับรอง WHT) เท่านั้น — **ไม่ทำธุรกรรมโอนเงินจริง**
- ทะเบียนคุมเช็ค: เลขที่เช็ค, ธนาคาร, วันที่, ผู้รับ, จำนวน, สถานะ (พิมพ์/จ่าย/ยกเลิก/คืน)
- พิมพ์ผ่านกลไกเดิมของระบบ (DocRenderer/mPDF — ดูบันทึก doc-render-traps)
- เมื่อบันทึกจ่าย → `payable_status = paid`, บันทึกเลขเช็ค/วันจ่าย

### 6.4 WHT
- ออก **หนังสือรับรองหัก ณ ที่จ่าย** ต่อการจ่าย + สรุป **ภ.ง.ด.3/53** รายเดือน (export)

## 7. ช่วง 6 — ตัดจ่าย + รายงาน

- ยืนยันจ่ายสำเร็จ → `settled` (หรือ `partially_settled`) → ยอดคงเหลือในทะเบียนลด
- **รายงานที่ต้องมี:**
  1. **ยอดคงเหลือรายเจ้าหนี้** (subsidiary ledger รายตัว: ยอดยกมา/ตั้งหนี้/ตัดจ่าย/คงเหลือ)
  2. **รายงานอายุหนี้ (Aging)** — ช่วง 0–30 / 31–60 / 61–90 / >90 วัน
  3. **กระทบยอด GL** — Σ ทะเบียน = ยอดบัญชีคุมยอด (แจ้งเตือนเมื่อไม่ตรง)
  4. **สถานะเจ้าหนี้ / ทะเบียนคุมเช็ค / ภ.ง.ด.**
- ทุกยอดเงินแสดง 2 ตำแหน่ง, ปีงบทดสอบระวังใช้ปีอนาคต (ดูบันทึก finance-loan)

## 8. DB schema ที่เสนอเพิ่ม (ให้ Codex พิจารณา)

> ต่อจาก `finance_payable / finance_inbox / finance_voucher` เดิม — **ไม่แก้ตารางที่รันแล้ว** สร้าง migration ใหม่ (ดูบันทึก migration-drift)

| ตาราง | หน้าที่ |
|---|---|
| `finance_payable` (เพิ่มฟิลด์) | `payable_status`, `opening_balance` (flag), `settled_amount`, `settled_at` |
| `finance_payable_import_batch` | หัวชุดนำเข้า Excel (ไฟล์, ผู้นำเข้า, สรุปยอด, สถานะ) |
| `finance_bill_receipt` + `_item` | หัว/รายการใบรับวางบิล (1 บิล : หลายใบตั้งหนี้) |
| `finance_payment_voucher` + `_item` | ฎีกา/ขออนุมัติจ่าย + รายการใบที่จ่าย (ถ้า `finance_voucher` เดิมยังไม่ครบ) |
| `finance_cheque` | ทะเบียนคุมเช็ค |
| `finance_wht_certificate` | หนังสือรับรองหัก ณ ที่จ่าย |
| `finance_payable_ledger` (optional) | บรรทัดรายการเคลื่อนไหว (ตั้งหนี้/ตัดจ่าย) เพื่อ subsidiary ledger + aging เร็ว |

## 11. คำถามที่ต้องยืนยันก่อนลงมือ (ให้การเงิน/บัญชี/Codex)

1. **Post GL อัตโนมัติหรือไม่** — ระยะแรกทำแค่ทะเบียน+รายงานให้บัญชีคีย์เข้า GFMIS/GL เอง หรือจะให้ระบบสร้าง JE? (shadow-mode เดิมเลือก "ไม่ post") ✅ แนะนำคงไว้ก่อน
2. **อัตรา WHT** ตามประเภทค่าใช้จ่าย — ต้องได้ตารางอัตราจริงจากการเงิน (ค้างเดียวกับงานพัสดุ)
3. **พิมพ์เช็ค** — รูปแบบ/ธนาคาร/ตำแหน่งพิมพ์บนแบบฟอร์มเช็คจริง (ต้องได้ตัวอย่างเช็ค)
4. **ยอดยกมา** — ตั้งต้น ณ วันไหน, มีไฟล์ Excel ตัวอย่างจากระบบเดิมไหม (ขอไฟล์จริงเพื่อ fix template)
5. **1 บิลหลายใบตั้งหนี้ / จ่ายบางส่วน** — เกิดจริงบ่อยแค่ไหน (กำหนดความซับซ้อนเฟส 3–6)
6. **เลขที่เอกสาร** — รูปแบบเลขฎีกา/เลขรับบิล/เลขเช็ค ตามระเบียบหน่วยงาน
7. **การแบ่งงาน** — เฟส 2–6 Codex ทำเองทั้งหมด หรือให้ Claude ช่วยเฟส Excel (ต้องประสาน)
