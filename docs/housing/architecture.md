# ระบบบ้านพักและสวัสดิการ

## ขอบเขต

โมดูล `housing` ดูแลทะเบียนบ้านพักและแฟลต การขอและจัดสรรที่พัก
ผู้พักอาศัย บุคคลภายนอก ค่าใช้จ่าย การรับชำระ ใบเสร็จ และการเชื่อมงานซ่อม

## โครงสร้างสถานที่

```text
Building
└── Floor (ไม่บังคับสำหรับบ้านพัก)
    └── Unit
        └── Room
```

- บ้านพักหนึ่งหลังใช้หนึ่ง `Building` และหนึ่ง `Unit`
- แฟลตครอบครัวจัดสรรทั้ง `Unit`
- แฟลตโสดจัดสรรแยก `Room` ภายใน `Unit`
- ความจุเป็นข้อมูลเสริมและยังไม่ใช้ปิดกั้นการจัดสรร

## สถานะยูนิตและห้อง

| Code | ความหมาย |
|---|---|
| `vacant` | ว่าง |
| `occupied` | มีผู้พัก |
| `reserved` | จัดสรรแล้ว รอเข้าอยู่ |
| `move_out` | รอย้ายออก |
| `maintenance` | ปิดซ่อม |
| `inactive` | งดใช้งาน |

การเปลี่ยนสถานะจาก workflow ต้องทำผ่าน service กลางในระยะ workflow
ไม่ให้ view หรือ controller หลายจุดคำนวณสถานะแยกกัน

## การอนุมัติคำขอเข้าพัก

```text
draft
→ submitted
→ staff_review
→ committee_review
→ approved / rejected
→ allocated
→ active
```

ระบบเก็บผลมติ วันที่ เลขอ้างอิง ผู้บันทึก และเอกสารแนบเท่านั้น
ไม่เก็บคะแนนหรือกระบวนการคัดเลือกของคณะกรรมการ

## หลักการเงิน

- ค่าใช้จ่ายเป็นแบบ manual ในระยะแรก
- สมาชิกครอบครัวและผู้พักภายนอกเป็นฐานประกอบยอด แต่เจ้าหน้าที่ผู้ครอบครองหลักเป็นลูกหนี้
- แยกใบแจ้ง การรับชำระ การจัดสรรยอด และใบเสร็จออกจากกัน
- เอกสารที่ยืนยันแล้วแก้ไขไม่ได้ ใช้การยกเลิกพร้อม audit log

## จุดเชื่อมระบบเดิม

| ระบบ | การเชื่อม |
|---|---|
| HR | เจ้าหน้าที่ผู้ครอบครองและผู้ยื่นคำขอ |
| filemanager | เอกสารคำขอ หลักฐานการโอน และไฟล์ใบเสร็จ |
| helpdesk | งานซ่อมของอาคาร ยูนิต ห้อง และเครื่องใช้ |
| telegrambot | การแจ้งสถานะ ใบแจ้ง รับชำระ และใบเสร็จ |
| approveV2 | ใช้เฉพาะงานอนุญาตที่เหมาะกับผู้อนุมัติรายบุคคล |
| am | เชื่อมครุภัณฑ์ประจำห้องผ่าน `asset_id` |
