# การใช้ระบบสแกนใบหน้าเพื่อ Login

## สรุปสั้นๆ

**ใช้ได้** โดยมี 2 แนวทางหลัก:

1. **WebAuthn + Biometric บนอุปกรณ์ (Face ID / Windows Hello)** — แนะนำ: ปลอดภัย มาตรฐาน ไม่เก็บรูปใบหน้าบนเซิร์ฟเวอร์
2. **สแกนใบหน้าผ่านกล้องเว็บ (Custom)** — ใช้กล้องถ่ายหน้าแล้วเทียบกับข้อมูลที่เก็บไว้: ทำได้แต่ต้องดูแลเรื่องความปลอดภัยและความเป็นส่วนตัว

---

## สถานะระบบ Login ปัจจุบัน

- **Username + Password** (LoginForm)
- **ThaiD** (ยืนยันตัวตนด้วยบัตรประชาชน)
- **Provider callback** (hash/callback จากระบบภายนอก)
- **Line Login**

ยังไม่มี WebAuthn หรือการยืนยันตัวด้วยใบหน้า

---

## แนวทางที่ 1: WebAuthn + Face ID / Windows Hello (แนะนำ)

### คืออะไร
ผู้ใช้ลงทะเบียน "ตัวตนบนอุปกรณ์" (เช่น Face ID บน iPhone/Mac, Windows Hello บน PC) กับบัญชีของเรา เมื่อล็อกอิน ระบบจะขอให้อุปกรณ์ยืนยันใบหน้า (หรือลายนิ้วมือ) แล้วส่ง cryptographic assertion มาที่เซิร์ฟเวอร์ — **ข้อมูลใบหน้าไม่ถูกส่งมาให้เรา** อยู่บนอุปกรณ์เท่านั้น

### ข้อดี
- ปลอดภัยและเป็นมาตรฐาน (WebAuthn / FIDO2)
- ไม่ต้องเก็บรูปใบหน้าหรือ template บนเซิร์ฟเวอร์ (ลดความเสี่ยงและเรื่อง PDPA)
- รองรับโดย Safari (Face ID), Chrome/Edge (Windows Hello, Android Face Unlock)
- ใช้ร่วมกับ username/password ได้ (เป็นตัวเลือกเพิ่ม)

### ข้อจำกัด
- ต้อง **HTTPS**
- ผู้ใช้ต้อง **ลงทะเบียน WebAuthn ต่ออุปกรณ์** (อุปกรณ์ใหม่ต้องลงทะเบียนใหม่)
- เบราว์เซอร์/อุปกรณ์ต้องรองรับ (มือถือ/แท็บเล็ตส่วนใหญ่รองรับ)

### สิ่งที่ต้องทำ
1. **Backend (Yii2)**  
   - เก็บ credential (credential_id, public_key) ต่อ user  
   - API สำหรับลงทะเบียน: สร้าง challenge, รับ assertion จาก client, ตรวจสอบและบันทึก  
   - API สำหรับล็อกอิน: สร้าง challenge, รับ assertion, ตรวจสอบแล้วสร้าง session (login)

2. **Frontend**  
   - ใช้ `navigator.credentials.create()` ตอนลงทะเบียน  
   - ใช้ `navigator.credentials.get()` ตอนล็อกอิน (ระบบจะป๊อป Face ID / Windows Hello ให้เอง)  
   - ส่งผลลัพธ์ไปที่ API ด้านบน

3. **หน้า Login**  
   - เพิ่มปุ่ม "เข้าสู่ระบบด้วย Face ID / Windows Hello"  
   - ถ้าผู้ใช้เคยลงทะเบียนบนอุปกรณ์นี้ จะสามารถล็อกอินด้วยใบหน้าได้

## แนวทางที่ 2: สแกนใบหน้าผ่านกล้อง (Custom)

### คืออะไร
เปิดกล้องบนเว็บ → ถ่ายภาพใบหน้า → ส่งไปประมวลผล (ในเบราว์เซอร์ เช่น face-api.js หรือส่งไป backend) → เทียบกับ "รูปใบหน้าที่ลงทะเบียนไว้" หรือ face template ของ user → ถ้าตรงกันให้ถือว่าผ่านและทำ login

### ข้อดี
- ใช้ได้บนอุปกรณ์ที่มีกล้อง ไม่ต้องพึ่ง Face ID/Windows Hello
- ควบคุม UX ได้เต็ม (หน้าจอสแกนหน้าเอง)

### ข้อจำกัดและความเสี่ยง
- **ต้องเก็บข้อมูลใบหน้า** (รูปหรือ template) ในระบบ → กระทบความเป็นส่วนตัว และ PDPA
- **Liveness** — ต้องกันการเอารูป/วิดีโอมาสวม (เช่น ขยับหน้า หรือ blink detection)
- ความแม่นยำ (แสง, มุม, แว่น) และ UX (ผู้ใช้บางคนไม่สะดวกให้ถ่ายหน้า)
- ต้องมีขั้นตอน **ลงทะเบียนใบหน้า** (ถ่ายหน้าแล้วผูกกับ user)

### สิ่งที่ต้องทำ
1. เก็บรูปใบหน้าหรือ face descriptor ต่อ user (ต้องเข้ารหัส/จำกัดการเข้าถึง)
2. หน้า "ลงทะเบียนใบหน้า" และ "ล็อกอินด้วยใบหน้า" ที่เปิดกล้องและส่งภาพ/ข้อมูลไปตรวจ
3. Backend หรือ frontend (เช่น face-api.js) ทำการเทียบหน้า + ตรวจ liveness
4. นโยบายความเป็นส่วนตัวและ consent ให้ชัดเจน

---

## คำแนะนำ

- **ถ้าต้องการ "ล็อกอินด้วยใบหน้า" แบบปลอดภัยและไม่เก็บรูปใบหน้า:**  
  → ใช้ **แนวทางที่ 1 (WebAuthn + Face ID / Windows Hello)**  
  ผู้ใช้จะสแกนใบหน้าผ่านระบบของอุปกรณ์ แล้วเว็บเราได้รับแค่ cryptographic response มาเช็กว่าเป็นคนเดิมที่ลงทะเบียนไว้

- **ถ้าต้องการให้ "สแกนใบหน้าผ่านกล้องเว็บ" โดยไม่พึ่ง Face ID/Windows Hello:**  
  → ใช้ **แนวทางที่ 2** ได้ แต่ต้องออกแบบเรื่องเก็บข้อมูลใบหน้า, liveness และ PDPA ให้ดี

---

## ขั้นตอนถัดไป (ถ้าเลือก WebAuthn)

1. ออกแบบตาราง/ฟิลด์เก็บ credential (user_id, credential_id, public_key, counter)
2. ติดตั้ง/ใช้ library ที่รองรับ WebAuthn ฝั่ง PHP (เช่น web-auth/webauthn-lib หรือไลบรารีอื่นที่รองรับ FIDO2)
3. สร้าง API ลงทะเบียน + API ล็อกอิน (challenge/assertion)
4. เพิ่มปุ่มและ JS บนหน้า login สำหรับ "เข้าสู่ระบบด้วย Face ID / Windows Hello"
5. เพิ่มหน้า/ขั้นตอน "ลงทะเบียน Face ID" หลังล็อกอิน (เช่น ในเมนูตั้งค่าหรือโปรไฟล์)

ถ้าต้องการให้ช่วยออกแบบตาราง + ตัวอย่าง flow (ลงทะเบียน/ล็อกอิน) หรือร่างโค้ดสำหรับแนวทางที่ 1 หรือที่ 2 บอกได้ว่าจะเริ่มจากฝั่ง backend หรือ frontend ก่อน
