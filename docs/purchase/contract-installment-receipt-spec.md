## 1. ปัญหา

ใบสั่งซื้อ (PO) ออกครั้งเดียวเต็มวงเงินสัญญา แต่การตรวจรับและการเบิกจ่ายเกิดเป็นรายงวด (ส่วนใหญ่รายเดือน)
ตัวอย่างจริงปีงบ 2569:

| PR | รายการ | วงเงิน | วิธี |
|---|---|---:|---|
| PR-690241 | จ้างเหมาบริการฟอกเลือดด้วยเครื่องไตเทียม | 15,997,500 | e-bidding |
| PR-690019 | จ้างเหมาบริการตรวจเอกซเรย์คอมพิวเตอร์ความเร็วสูง | 4,000,000 | e-bidding |

โปรแกรมปัจจุบันผูกทุกอย่างไว้ที่ "ใบ" 1 ใบ:

- `orders.status` เดินเส้นเดียว 1→7 — ตรวจรับ (5) ได้ครั้งเดียว, ส่งการเงิน (7) ได้ครั้งเดียว
- `data_json.gr_date` มีวันตรวจรับได้วันเดียว
- `finance_inbox` ผูก 1 ใบ = 1 รายการ (`source_type`+`source_id`=order.id) ยอด = ทั้งใบ
- แดชบอร์ด /sm นับ "ตรวจรับ" เต็มวงเงินในเดือนเดียว → กราฟโด่ง, ส่วน "ขอซื้อ" โด่งในเดือนที่ทำ PR

ผลคือ ตรวจรับเดือนที่ 1 ไม่ได้ถ้าไม่ปิดทั้งใบ และถ้าปิดทั้งใบ การเงินจะตั้งเจ้าหนี้เต็ม 16 ล้านทีเดียว

## 2. รูปแบบสัญญาที่ต้องรองรับ

| รูปแบบ (`billing_mode`) | ลักษณะ | ตัวอย่าง | ยอดแต่ละงวด |
|---|---|---|---|
| `lump` | ส่งมอบ/ตรวจรับครั้งเดียว (แบบเดิม) | ซื้อครุภัณฑ์ | — ใช้โฟลว์เดิม |
| `fixed` | งวดตายตัวตามสัญญา | รปภ., ทำความสะอาด, เช่ารถ | กำหนดล่วงหน้า (งวดละ x บาท) |
| `unit_price` | ราคาต่อหน่วย ตามปริมาณจริง ไม่เกินวงเงิน | ฟอกไต (ราคา/ครั้ง), CT (ราคา/ครั้ง) | ปริมาณจริง × ราคาต่อหน่วย |

หมายเหตุ: ฟอกไตและ CT น่าจะเป็น `unit_price` — 15,997,500 คือเพดาน ไม่ใช่ยอดที่ต้องจ่ายครบ **(ต้องยืนยันกับงานพัสดุ)**

การซื้อวัสดุแบบแบ่งส่งหลายงวด (เช่น ออกซิเจน, น้ำยา Lab) ใช้โครงเดียวกันได้ แต่แต่ละงวดต้องลงคลังด้วย → แยกเป็นเฟสหลัง

## 3. ของที่มีอยู่แล้ว (ใช้ต่อ ไม่สร้างซ้ำ)

- `purchase_contract` — หัวสัญญา ผูก `order_id` (UNIQUE), มีวงเงิน/ภาษีหัก ณ ที่จ่าย/ค่าปรับ/วันเริ่ม-สิ้นสุด (ยังไม่มีข้อมูลจริง 0 แถว)
- `purchase_contract_milestone` — งวดงานตามสัญญา (กำหนดการ) มี `amount`, `due_date`, `receive_date`, `fine_*` (0 แถว)
- `purchase_bond` — หลักประกันสัญญา
- `orders` name=`committee` — กรรมการตรวจรับ แต่งตั้งครั้งเดียวต่อใบ ใช้ต่อได้ทุกงวด
- `finance_inbox` — มี `source_type`/`source_id` อิสระ รับประเภทใหม่ได้โดยไม่แก้ตาราง

## 4. หลักการออกแบบ

1. **แยก "กำหนดการ" ออกจาก "การตรวจรับจริง"**
   `milestone` = งวดตามสัญญา (แผน) · `receipt` = การตรวจรับที่เกิดขึ้นจริง (ผลงาน)
   สัญญา `fixed` → receipt อ้าง milestone 1:1 · สัญญา `unit_price` → ไม่มี milestone หรือมีเป็นรายเดือนแต่ยอดตามจริง
2. **หน่วยที่ส่งการเงิน = receipt 1 งวด** ไม่ใช่ใบสั่งซื้อ → `finance_inbox.source_type='contract_receipt'`
3. **ห้ามนับซ้ำ**: ใบที่ตรวจรับรายงวดต้องปิดทางส่งการเงินทั้งใบ (guard ฝั่ง order) — บทเรียนเดียวกับหลักประกันที่ต้นแบบนับซ้ำ
4. **ไม่เพิ่มคอลัมน์ใน `orders`** — ตัวชี้ว่าใบไหนตรวจรับรายงวดคือ "มีสัญญาผูก และ `billing_mode` ≠ `lump`"
5. **ยอดคงเหลือคำนวณจาก receipt** ไม่เก็บซ้ำ (วงเงิน − ผลรวม receipt ที่ไม่ยกเลิก)
6. ปีงบของแต่ละงวดยึด **วันตรวจรับของงวด** (สัญญาข้ามปีงบได้ แต่ละงวดลงปีของตัวเอง)

## 6. โฟลว์

1. ออก PO เต็มวงเงินตามเดิม (`orders.status` 4) — วงเงินเต็มยังเป็น **ภาระผูกพัน**
2. สร้าง/ผูกสัญญา เลือก `billing_mode` · สัญญา `fixed` สร้างงวดอัตโนมัติจากวันเริ่ม-สิ้นสุด + รอบเดือน
3. แต่ละเดือน: บันทึกตรวจรับงวด (receipt) → กรรมการตรวจรับ → `received`
4. กด "ส่งการเงิน" รายงวด → สร้าง `finance_inbox` (source_type=`contract_receipt`, source_id=receipt.id, amount=ยอดงวด) → `sent_finance`
5. การเงินรับรอง & ตั้งเจ้าหนี้ **ตามโฟลว์เดิมทุกอย่าง** (ไม่ต้องแก้ฝั่ง finance นอกจาก snapshot builder ตัวใหม่)
6. ปิดสัญญา: งวดสุดท้าย หรือปิดเองพร้อมเหตุผล → คำนวณเงินเหลือจ่าย = วงเงิน − ยอดรับจริง → คืนภาระผูกพัน
7. `orders.status` ของใบรายงวด: ค้างที่ 4 ระหว่างมีงวด → เมื่อปิดสัญญาขยับเป็น 7 (ส่งการเงินครบ) — **ไม่ผ่านปุ่มส่งการเงินทั้งใบ**

## 9. ข้อตกลงจากผู้ใช้ (2026-09-25)

1. ฟอกไต/CT จ่ายรายเดือน **ตามจำนวนจริง ไม่เท่ากันทุกเดือน** → `unit_price`
2. รองรับ **ทั้ง `fixed` และ `unit_price`**
3. PO ออกยอดเต็ม · การตรวจรับแต่ละงวดมี **วันที่ + ยอดเงินที่เรียกเก็บ** · บัญชีตั้งหนี้ตามยอดเรียกเก็บรายเดือน (ตรงกับ receipt → finance_inbox รายงวด)
4. ที่ผ่านมาไม่มีการตรวจรับรายเดือนในระบบ (รับเป็นยอดรวม) → ต้องทำให้ตรวจรับรายเดือนได้
5. ทำแม่แบบ "บันทึกรายงานผลการตรวจรับงวด" ใน /purchase/doc ด้วย (เฟส 3)

ขอบเขต: ผู้ใช้คาดว่าเป็นกลุ่มที่จัดซื้อด้วย e-bidding เป็นหลัก แต่ **ตัวเปิดใช้ = `billing_mode` บนสัญญา ไม่ผูกกับวิธีจัดซื้อ** (สัญญารายปีวิธีอื่นใช้ได้ด้วย)
ฐานทดสอบ (ข้อมูลถึง ส.ค. 69) มีใบ e-bidding ปี 2569 เพียง 3 ใบ: PR-690241 ฟอกไต, PR-690019 CT (สถานะ 3), PR-690016 ตรวจวิเคราะห์ Lab 700,000 (สถานะ 6 ตรวจรับเต็มใบไปแล้ว)
