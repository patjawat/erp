# HR dashboard: HA ฉบับที่ 6

วันที่วิเคราะห์: 8 กันยายน 2569 · เป้าหมาย: ให้ HR เห็นสถานการณ์ ตัดสินใจ และติดตามผลการปรับปรุง โดยคง Yii2 / Bootstrap และสิทธิ์เดิมของ ERP

## หลักฐานและขอบเขต

- ตรวจโค้ด `modules/hr/controllers/DefaultController.php` และ `modules/hr/views/default/dashboard.php` รวมถึงเส้นทางพัฒนาบุคลากร สมรรถนะ และสุขภาพที่มีอยู่จริง
- เว็บไซต์ที่ผู้ใช้ระบุเปลี่ยนไปหน้าเข้าสู่ระบบ จึงยังไม่ได้ยืนยันตัวเลขหรือหน้าจอหลังเข้าสู่ระบบของ production
- ภาพแนบใช้เป็นแนวคิดหมวด HR เท่านั้น ตัวเลข ค่าเป้าหมาย และข้อความในภาพไม่ใช่ข้อมูลโรงพยาบาลหรือคำสั่งให้พัฒนา
- [สรพ.: มาตรฐานโรงพยาบาลและบริการสุขภาพ](https://www.ha.or.th/th/Contents/มาตรฐานโรงพยาบาลและบริการสุขภาพ%20%28HA%29) ระบุเริ่มใช้ฉบับที่ 6 ในการประเมินรับรองตั้งแต่ 1 ตุลาคม 2569
- [แบบประเมิน SAR 2026 ฉบับที่ 6 ของ สรพ.](https://backend.ha.or.th/fileupload/DOCUMENT/00183/280fa7c4-8100-433d-b114-c78372802bf2.pdf) หน้าเอกสาร 16–18 (PDF หน้า 17–19) ใช้ตรวจสอบการเชื่อม I-5.1 สภาพแวดล้อมของบุคลากร, I-5.2 ความผูกพันของบุคลากร และผลลัพธ์ IV-3
- สูตรและตัวชี้วัดด้านล่างเป็นข้อเสนอเชิงออกแบบสำหรับโรงพยาบาล ไม่ใช่รายการ KPI บังคับหรือค่าเกณฑ์ผ่านของ HA ต้องตกลงนิยามกับ HR/ทีมคุณภาพก่อนนำไปประเมินผลงาน

## ผลวิเคราะห์หน้าเดิม

จุดแข็ง: เลือกปีงบประมาณได้ แยกกลุ่มงาน ตำแหน่ง ประเภทพนักงาน เพศ ช่วงวัย และอายุงานได้ มีรายการเบื้องหลัง KPI และกราฟที่ใช้กรองข้อมูลต่อได้ มี snapshot ประวัติบุคลากรสำหรับปีเก่า

ช่องว่างสำคัญ:

1. ข้อมูลส่วนใหญ่บอกโครงสร้างคน แต่ยังตอบไม่ได้ว่าคนเพียงพอต่อบริการหรือไม่ เพราะไม่มีกรอบอัตรากำลังและภาระงานให้เปรียบเทียบ
2. ตัวเลขพ้นจากหน่วยงานรวมหลายเหตุผล จึงใช้แทนอัตราลาออกโดยสมัครใจไม่ได้ และยังไม่มีจำนวนคนเฉลี่ยสำหรับตัวหาร
3. มี `leftThisYearBreakdown` ส่งจาก controller แต่หน้าเดิมยังไม่ได้ใช้แสดงเหตุผลให้ HR วิเคราะห์
4. อายุงานเฉลี่ยบอกประสบการณ์ในองค์กร แต่ไม่แทนสมรรถนะ ผลการปฏิบัติงาน หรือความพร้อมผู้สืบทอด
5. Query กราฟอายุเดิมตัดอายุ 60 ปีขึ้นไป และคำนวณช่วงอายุด้วยผลต่างปี จึงไม่ควรใช้กราฟนี้คาดวันเกษียณหรือวัดความครบถ้วนของวันเกิดโดยตรง
6. การเคลื่อนไหวใช้ช่วงปีงบประมาณเต็มตามวันที่ในทะเบียน ขณะที่ headcount เป็น snapshot ณ วันอ้างอิง ส่วนต่างรับเข้า–พ้นสภาพจึงไม่ใช่ยอดคงเหลือต้นปี–ปลายปี โดยเฉพาะเมื่อกรองหน่วยงานหรือมีการย้าย
7. ผังองค์กรและจำนวนทีมเป็นยอดทะเบียนรวม ไม่ได้ใช้ตัวกรองบุคลากรเดียวกับจำนวนคน
8. ยังไม่มีชุดข้อมูล HA ที่รวมเป้าหมาย แนวโน้ม ผู้รับผิดชอบ และผลหลังแก้ไขครบวงจร ข้อมูลย้อนหลังขึ้นกับความครบถ้วนของประวัติที่บันทึก

## สิ่งที่ปรับในรอบนี้

- เปลี่ยนชื่อหน้าให้สื่อการวางแผน HR และแก้ข้อความสรุปให้ระบุว่าเป็นข้อมูลตามตัวกรอง
- จัดลำดับ KPI เป็นจำนวนคน → บรรจุใหม่ → พ้นจากหน่วยงาน → อายุงาน → โครงสร้าง โดยคงรายการและการกดดูรายละเอียดทุกตัวเดิม
- เพิ่มส่วนต่างรับเข้า–พ้นสภาพ พร้อมคำแนะนำที่เปลี่ยนตามค่าบวก/ลบ/ไม่มีข้อมูล โดยไม่ตีความว่าผ่านเกณฑ์ความเพียงพอ
- แสดงจำนวนพ้นสภาพแยกเหตุผลจากข้อมูลที่ controller ส่งอยู่แล้ว เข้ารหัสข้อความก่อนแสดงผล
- เพิ่มกราฟแท่งเปรียบเทียบบรรจุใหม่–พ้นจากหน่วยงานและกราฟโดนัทสัดส่วนเหตุผล ด้วย ApexCharts ที่ ERP ใช้อยู่ มีจำนวน/เปอร์เซ็นต์ในคำอธิบายและเปิดตารางตรวจสอบได้ ไม่มีการสร้างแนวโน้มรายเดือนจากยอดรวมรายปี
- กราฟใหม่ใช้สีจาก Bootstrap tokens และปรับเมื่อเปลี่ยน theme; หาก JavaScript/กราฟใช้ไม่ได้ยังแสดงข้อมูลตัวเลขและตารางไว้ ตัวเลขศูนย์ไม่แสดงเป็นสัดส่วนโดนัท
- เพิ่มหัวข้อติดตาม HA สี่ด้านที่เปิดอ่านรายละเอียดได้ มีข้อจำกัด ตัวชี้วัดเสนอใช้ และลิงก์ไปหน้าข้อมูลจริง โดยแจ้งว่าหน้าปลายทางมีตัวกรองของตนเอง
- ส่วนใหม่ใช้ Bootstrap responsive grid, semantic theme classes, native details/summary และตารางที่เลื่อนได้ ไม่เพิ่ม CSS สีตายตัว ไลบรารี หรือคำขอฐานข้อมูล
- ไม่แก้ controller, query, schema, route, สิทธิ์ หรือ AJAX เดิม

## ตัวชี้วัดที่เสนอและข้อมูลที่ต้องเตรียม

| ประเด็น | ใช้ตัดสินใจ | นิยาม/สูตรเสนอ | ข้อมูลที่ต้องมีเพิ่มเติม | ผู้รับผิดชอบ / รอบทบทวนเสนอ |
|---|---|---|---|---|
| กำลังคนและความต่อเนื่อง (I-5.1) | จัดคนตามบริการและแผนทดแทน | ช่องว่าง FTE = FTE ต้องการ − FTE ปฏิบัติงาน; แสดงทั้งสองค่าและรุ่นกรอบ | กรอบอนุมัติ เวลาปฏิบัติงานจริง ภาระงานรายวิชาชีพ/เวร | HR + หัวหน้าหน่วยงาน / รายเดือน |
| การรักษาบุคลากร (I-5.2) | วิเคราะห์เหตุสูญเสียคนและแก้ปัญหา | ผู้ลาออกโดยสมัครใจ ÷ headcount เฉลี่ยในช่วง × 100 | รหัสเหตุผลที่แยกลาออก ย้าย เกษียณ เสียชีวิต; snapshot จำนวนคนรายเดือนหรือรายวันตามวิธีที่ตกลง | HR / รายเดือนและย้อนหลัง 12 เดือน |
| การสรรหา (สนับสนุน I-5.1) | จัดลำดับตำแหน่งเติมยาก | ค่ามัธยฐานวันตั้งแต่อนุมัติคำขอจนยอมรับข้อเสนอ; รายงานงานที่ยังไม่ปิดแยก | เลขคำขอ วันที่เปิด วันที่รับข้อเสนอ สถานะ จำนวนอัตรา | HR / รายเดือน |
| สมรรถนะ (I-5.1, I-5.2) | วาง IDP ตามความเสี่ยงของงาน | ผู้ประเมินครบ ÷ ผู้ต้องประเมิน × 100; ผู้ผ่านเกณฑ์ ÷ ผู้ประเมินครบ × 100 แสดงแยกกัน | ความคาดหวังตามบทบาท รอบประเมิน ผลประเมิน วันติดตาม IDP | HRD + หัวหน้าวิชาชีพ / รายไตรมาส |
| ใบอนุญาต/คุณสมบัติ (สนับสนุน I-5.1) | ตรวจความพร้อมก่อนมอบหมายหน้าที่ | ผู้มีใบอนุญาตที่ตรวจสอบแล้วและยังใช้ได้ ÷ ผู้ต้องมี × 100 | บทบาทที่ต้องมีใบอนุญาต วันหมดอายุ วันที่/ผู้ตรวจสอบ และจำนวนที่ข้อมูลยังไม่ครบ | หัวหน้าวิชาชีพ + HR / รายเดือน |
| การพัฒนาและผลลัพธ์ (I-5.2) | เลือกแผนพัฒนาที่ช่วยปิดช่องว่างจริง | ผู้ปิดช่องว่างได้ตามผลประเมินติดตาม ÷ ผู้ครบกำหนดติดตาม × 100 | เป้าหมายก่อนอบรม ผลหลังนำไปใช้ ผู้ประเมิน กำหนดติดตาม; แยกจากชั่วโมงอบรม | HRD / รายไตรมาส |
| สุขภาพและความปลอดภัย (I-5.1) | ดูแลกลุ่มเสี่ยงและปิดเหตุจากงาน | ผู้ตรวจครบตามความเสี่ยง ÷ ผู้เข้าเกณฑ์ × 100; จำนวนเหตุจากงานและสถานะแก้ไขแยกกัน | กลุ่มสัมผัส รายการตรวจที่ต้องทำ ผลความครบถ้วน ทะเบียนเหตุและแผนแก้ไข | อาชีวอนามัย + IC + HR / รายเดือน |
| ภาระงานและเวลาพัก (สนับสนุน I-5.1) | ปรับเวรและป้องกันความล้า | จำนวนผู้เกินเกณฑ์ชั่วโมง/เวลาพักตามนโยบายที่อนุมัติ; ชั่วโมง OT แยกจากวันลา | เวรจริง ชั่วโมงสะสม เกณฑ์ตามบทบาท ข้อยกเว้นที่อนุมัติ | หัวหน้าหน่วยงาน + HR / รายสัปดาห์ |
| ความผูกพัน (I-5.2) | เลือกเรื่องปรับสภาพการทำงาน | คะแนนตามเครื่องมือสำรวจเดียวกัน พร้อมผู้ตอบ ÷ ผู้ได้รับเชิญ × 100 | รุ่นแบบสำรวจ ช่วงสำรวจ จำนวนผู้ตอบ/เชิญ และแผนติดตาม | HR + ทีมคุณภาพ / รอบสำรวจและรายไตรมาส |
| ต้นทุนบุคลากร (ตัวชี้วัดบริหารประกอบ) | วางงบและประเมินต้นทุนทางเลือก | ค่าใช้จ่ายบุคลากรตามนิยามบัญชี ÷ FTE เฉลี่ยในช่วง | เงินเดือน OT สวัสดิการ แหล่งงบ และ FTE; ไม่รวมรายการซ้ำ | การเงิน + HR / รายเดือน |

ทุกตัวชี้วัดต้องแสดงช่วงเวลา หน่วย ตัวตั้ง ตัวหาร ขอบเขตตัวกรอง แหล่งข้อมูล วันที่ปรับปรุง และความครบถ้วน เปรียบเทียบช่วงเวลาเท่ากัน เช่น YTD ถึงวันเดียวกัน การแสดงย้อนหลังต้องไม่ใช้ snapshot คนปัจจุบันแทนอดีตโดยไม่แจ้ง

## วิธีนำไปใช้ในที่ประชุม HR

1. เลือกปีและกลุ่มงาน → ดูคนปฏิบัติงาน รับเข้า พ้นสภาพ และเหตุผล → กด KPI เพื่อตรวจรายการตามสิทธิ์
2. เทียบกับภาระงานจริงและกรอบอัตรากำลัง → เลือกปัญหาที่กระทบความต่อเนื่องของบริการ → ตั้งเจ้าของงานและวันติดตาม
3. ใช้หัวข้อ HA ตรวจว่าหลักฐานใดยังขาด → เปิดทะเบียนต้นทาง → ยืนยันตัวกรองและความครบถ้วนก่อนนำรายงานมาเปรียบเทียบ
4. บันทึกปัญหา เป้าหมาย วิธีแก้ ผู้รับผิดชอบ กำหนดเสร็จ และผลก่อน/หลังในระบบงานที่โรงพยาบาลใช้ ปัจจุบัน dashboard ยังไม่ได้เพิ่มทะเบียนแผนแก้ไข

## ขอบเขตการต่อยอด

แผนรายละเอียดการเก็บความผูกพันและเชื่อมโมดูลที่ตรวจโค้ดแล้วอยู่ใน `docs/hr-engagement-data-plan.md` ครอบคลุม schema เสนอ สิทธิ์ สูตรคะแนน ขอบเขตความลับ และลำดับพัฒนา ยังไม่มีการสร้างตารางหรือรัน migration

ขั้นแรกต้องตกลงนิยามข้อมูลและเจ้าของกับ HR/ทีมคุณภาพ จากนั้นทำ service รวมข้อมูลโดยใช้สิทธิ์เดิมของแต่ละโมดูล ทดสอบเรื่องช่วงเวลา การกรอง ตัวหาร ศูนย์/ไม่มีข้อมูล และบุคลากรย้ายหน่วยงาน ก่อนนำคะแนนและแนวโน้มขึ้น dashboard

ไม่อนุมานความเสี่ยงลาออก ผลงาน หรือความเหมาะสมรายบุคคลจากอายุ เพศ สุขภาพ หรือวันลา ผลสุขภาพและแบบสำรวจควรแสดงเป็นภาพรวมตามสิทธิ์ ใช้เกณฑ์จำนวนขั้นต่ำของกลุ่มที่องค์กรอนุมัติก่อนเปิด drill-down หรือส่งออก ไม่ใช้ 0 หรือสีเขียวแทนข้อมูลที่ยังไม่ครบ

## การตรวจสอบ

ตรวจ PHP syntax ของสอง view และ render ส่วนใหม่ด้วยข้อมูลสังเคราะห์แยกจากฐานข้อมูล ทดสอบส่วนต่างบวก/ลบ/ศูนย์/ไม่มีข้อมูล รวมถึงการ escape เหตุผลพ้นสภาพ ตรวจ layout desktop/mobile และ light/dark จาก preview โดยต้องแยกผลทดสอบนี้ออกจากการยืนยัน production

ก่อนนำขึ้นระบบจริง ยังต้องทดสอบหลังเข้าสู่ระบบ: ตัวกรองปี/หน่วยงาน, การเปิด KPI ทุกตัว, chart drill-down/AJAX, สิทธิ์หน้าพัฒนาบุคลากรและสุขภาพ, ข้อมูลเคลื่อนไหวที่เทียบทะเบียนได้ และกรณีปีเก่าที่ประวัติไม่ครบ
